### **Improved Portfolio Project Prompt**

**Goal:** Create a compelling portfolio entry that clearly tells the story of your project, even if it solves multiple problems. Ensure each problem is separate and easy to follow. **No code snippets** - focus on concepts and impact.

---

## **Prompt for GitHub Repo Analysis**

**Analyze this GitHub repository and provide a structured MDX portfolio entry:**

**Project Repository**: [paste GitHub URL]
**README Content**: [paste README.md]

---

### **1️⃣ CATCHY TITLE & HOOK**

* **Title**: Idea-driven, benefit-focused (not generic).
  * Bad: "E-Commerce Platform"
  * Good: "AI Shopping Assistant That Predicts What You Need"
* **Description (Hook)**: One punchy sentence (max 120 chars) highlighting **primary value**.

### **8️⃣ MDX FORMATTING RULES (CRITICAL)**

**⚠️ Common MDX Parsing Errors to Avoid:**

1. **HTML Entities in Content**
   - ❌ NEVER use `&amp;`, `&lt;`, `&gt;`, `&quot;` in headings or regular text
   - ✅ Use actual characters: `&`, `<`, `>`, `"`
   - Example: Write "React & TypeScript" NOT "React &amp; TypeScript"

2. **Comparison Operators**
   - ❌ Don't use `<` or `>` directly: "<100ms", ">50%"
   - ✅ Use words: "under 100ms", "over 50%", "less than 100ms"

3. **Numbered Headings**
   - ❌ Don't start headings with numbers: `### 1. Problem` or `**1.`
   - ✅ Use words: `### Problem One:` or `**Challenge One:**`

4. **Mermaid Diagrams**
   - ✅ Use standard code blocks: ` ```mermaid `
   - ✅ No HTML entities in mermaid syntax
   - ✅ Keep diagram labels simple, avoid special characters
   - ❌ Don't use `<pre>` tags for mermaid

5. **HTML Tags in MDX**
   - ✅ Use actual tags: `<details>`, `<summary>`, `<br/>`
   - ❌ Don't use HTML entities for tags

6. **Line Breaks**
   - ✅ Use `<br/>` for explicit line breaks in features/lists
   - ✅ Use blank lines between sections

**Example of Correct Formatting:**
```mdx
## Key Features

🚀 **Feature One** - Description here<br/>
⚡ **Feature Two** - Description here<br/>
🎯 **Feature Three** - Description here

## Technical Challenges

**Challenge One: Type Safety** - Brief description

<details>
<summary>🔍 Deep Dive: Type Safety</summary>

**Problem**: Detailed explanation with & characters

**Solution**: How you solved it

**Impact**: Results under 100ms response time
</details>
```

### **9️⃣ CONTENT GUIDELINES**

**✅ Always Include:**
- Clear problem statements
- Visual diagrams (mermaid)
- Quantifiable impact metrics
- Architecture decisions explained
- Multiple problems if applicable

**❌ Avoid:**
- Code snippets (HR-friendly)
- Overly technical jargon
- Wall of text without visuals
- Generic descriptions
- HTML entities in content
- Numbered headings starting with digits
- Comparison operators like < or >

**🎯 Focus On:**
- Business impact
- Problem-solving approach
- Innovation & uniqueness
- Visual storytelling
- Clean MDX formatting
